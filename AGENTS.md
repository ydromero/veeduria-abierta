# AGENTS.md — Open Oversight (Veeduría Abierta)

Mandatory rules for any agent working in this repository. If a rule conflicts with a specific instruction, **ask the human before taking action**.

## Before starting any task
1. Read `principles.md` (constitutional layer — Tier E principles are never weakenable), `master-plan.md`, and `decision-log.md`. ADRs take precedence over any other document **except `principles.md`**, including research found in `docs/referencia/`.
2. If the task involves SECOP data, read `docs/diccionario-datos.md`.
3. Targeted reading: do not read large files in their entirety or process long outputs; use `offset`/`limit` and search queries instead.

## Stack (fixed, ADR-004)
Laravel 13 · PHP 8.5 · Livewire **4** · Bootstrap 5 · PostgreSQL 18 · Vite · Docker with Sail.
- All project commands must be executed using `./vendor/bin/sail ...`.
- **Livewire 4:** Do not assume Livewire 3 syntax. Verify the syntax in `vendor/livewire/livewire` or the v4 documentation before writing a component.
- Do not write custom JavaScript unless absolutely necessary and approved by the human.

## Core Domain Rules (violating these is a serious defect)
1. **Immutable raw data.** Official SECOP data must be stored unmodified and kept separate from any content generated by an LLM. All AI-generated content must be labeled and auditable (ADR-007). **(PR-05, PR-12)**
2. **Indicators, not accusations.** No text, variable name, view, or commit should imply that an individual or company is guilty. Use the term "risk indicator" instead (ADR-008). **(PR-09)**
3. **Reliability levels.** Never present data from level 2 or 3 as if it were level 1. Phase 1 uses only level 1. **(PR-06, PR-07)**
4. **Do not invent SECOP fields or endpoints.** If a field is not in `diccionario-datos.md`, check the API metadata or ask. Document what you discover. **(PR-06)**
5. **No secrets.** Never write keys, tokens, or passwords in code, commits, documents, logs, or messages. Do not read `.env` files by any means (including `grep`, `find`, or `cat`). If you need a configuration value, ask a human. **(PR-14)**
6. **No inauthentic behavior** on social networks or in content (no coordinated accounts or content designed to simulate the voices of citizens). **(PR-10)**

## Data and Ingestion
- Use cursor-based pagination keyed on `:id`. Never use `$offset` for bulk loads (ADR-002).
- Use SODA authentication with a Key ID and Key Secret retrieved from the configuration (ADR-003).
- All write operations that persist data must occur within a `DB::transaction`.
- Do not use dummy values ​​or artificial nulls to bypass `NOT NULL` constraints. If a critical piece of data is missing, treat it as an error, log it, and report it.
- Queue: use the `database` driver (ADR-005). Long-running tasks must be executed as background jobs, not within the web request cycle.
- Large tables: always use `paginate()`. Never load entire collections into Livewire properties.

## Testing
- Tests must run against the `testing` database, never the development database (ADR-006). Use `RefreshDatabase`.
- All new logic must be covered by tests. Run the tests before marking a task as complete. ## Safe Operation
- Do not execute destructive commands (deleting volumes, `migrate:fresh`, `rm -rf`, `docker system prune`) without explicit authorization from the human.
- Long-running builds and downloads should be triggered in the background, logged, and checked later; do not use a fixed timeout.
- This machine also hosts `sonnar-platform`. Do not modify its containers, ports, or volumes.
- Do not perform `git commit` or `git push`: propose the message and wait for confirmation (P-03).
- Treat user-uploaded or pre-existing files as originals; always work on copies.

## Language and Style
- Code, variable names, migrations, and commits: **English**. Documentation, interface text, and messages for citizens: **Spanish**, using clear language free of jargon.
- Any text explaining data to citizens must state the data source and its limitations.

## Human Decisions (Never Assume)
Vision and priorities · approving or modifying ADRs · legal and data interpretation · what is published and the tone of voice used · communication with partners (BuscaSECOP, demoanalitica, etc.) · secrets and access credentials · merges and publication.

## Definition of Done
A task is not considered complete until:
1. the code or document complies with the rules set out in this file;
2. all relevant tests pass;
3. the "living documents" affected by the change (listed in `.pi/memory/docs-map.md`) have been reviewed and updated—or an update has been proposed;
4. any decisions made have been proposed for inclusion in `registro-decisiones.md`;
5. the human has been informed of what has changed, what remains pending, and which decisions require their input.

## When Information Is Missing
Ask a question—provide one clear, specific question along with a recommended course of action. Do not fill in gaps with assumptions about data, laws, or business rules.
